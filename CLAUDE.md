## Code Style

- Keep code **simple**. Prefer the most straightforward solution that works.
- Don't overcomplicate. Avoid premature abstraction, clever tricks, or
  unnecessary layers. If a simpler approach exists, use it.
- Write code a **junior engineer** could read and understand without help.
  Favor clear names and obvious logic over brevity.
- Follow the existing **naming conventions**, formatting, and patterns already
  present in this codebase. Match the surrounding style.

## When Unsure

- **Ask before assuming.** If requirements, edge cases, or intent are unclear,
  ask a clarifying question instead of guessing.

## Before Finishing

- Run the **appropriate tests** for the code you changed and confirm they pass.
- If no relevant test exists, add a basic one or flag that it's missing.
